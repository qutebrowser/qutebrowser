52class PromptQueue(QObject): 

53 

54 """Global manager and queue for upcoming prompts. 

55 

56 The way in which multiple questions are handled deserves some explanation. 

57 

58 If a question is blocking, we *need* to ask it immediately, and can't wait 

59 for previous questions to finish. We could theoretically ask a blocking 

60 question inside of another blocking one, so in ask_question we simply save 

61 the current question on the stack, let the user answer the *most recent* 

62 question, and then restore the previous state. 

63 

64 With a non-blocking question, things are a bit easier. We simply add it to 

65 self._queue if we're still busy handling another question, since it can be 

66 answered at any time. 

67 

68 In either case, as soon as we finished handling a question, we call 

69 _pop_later() which schedules a _pop to ask the next question in _queue. We 

70 schedule it rather than doing it immediately because then the order of how 

71 things happen is clear, e.g. on_mode_left can't happen after we already set 

72 up the *new* question. 

73 

74 Attributes: 

75 _shutting_down: Whether we're currently shutting down the prompter and 

76 should ignore future questions to avoid segfaults. 

77 _loops: A list of local EventLoops to spin in when blocking. 

78 _queue: A deque of waiting questions. 

79 _question: The current Question object if we're handling a question. 

80 

81 Signals: 

82 show_prompts: Emitted with a Question object when prompts should be 

83 shown. 

84 """
